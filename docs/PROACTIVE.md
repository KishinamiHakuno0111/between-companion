# 本地主动联系

0.4.1 修复角色直接返回普通台词导致主动消息 JSON 解析失败的问题。联系计划和主动消息启用 API 的 JSON 输出模式，将历史角色台词作为数据提供，避免模型直接续写历史。格式无效、空白或截断时最多立即重试一次；持续格式错误会退避，不丢弃待办事件。升级后尚未过期的旧 JSON 错误任务会解除原来的一小时等待。已用 DeepSeek 官方 API 和虚构猫角色验证计划提取、到期生成、消息保存和通知回调。

0.4.0 新增。编辑角色，打开「允许 TA 主动联系」，也可在「设置 → 主动联系」按角色开启。默认关闭，不会自动为已有角色开启。

- **安排临近**：聊天中提到日期明确的未来安排，会保存联系计划；有具体时刻时默认提前 30 分钟关心。只有日期时采用当地当天 09:00。无法确定日期、假设和角色自行编造的事情不应建计划；模型提取仍可能判断不准，可在「编辑角色 → 待关心的安排」查看和取消。聊天中更改或取消安排也会更新计划。
- **久未聊天**：默认在最后一轮聊天结束后 6–12 小时之间选择一个时刻，结合当前时间和近期聊天自然问候。
- **停顿接话**：默认停顿 3 分钟后，只在最近有来回交流、模型判断话题仍未结束时接一句。告别、休息或结束话题后不会继续延长讨论。后台延迟超过 30 分钟便放弃这次接话。

设置中可以调整问候间隔、接话等待时间、每天次数和免打扰时间。默认每个角色每天最多 3 次，22:00–08:00 免打扰，以设备当前时区为准。收到任何主动消息后，只要没有新的玩家回复，就不会继续追发。事件超过安排时间两小时后过期，不积攒补发。

主动消息只使用该角色的人设、玩家在该角色中的身份、该角色的记忆与对话。内部触发任务不会被保存为用户消息，也不会进入对话摘要。事件、已尝试的联系和生成租约保存在本机 SQLite；重复唤醒不重复生成。玩家新发消息、关闭角色开关或取消事件时，过时的主动生成结果会被丢弃。

## 系统通知

Android 在「设置 → 主动联系」点「允许系统通知」，按系统提示授权。后台使用 Android JobScheduler 运行本地任务，无需电脑或服务器。点击通知会打开对应角色的聊天，包括首次启动和应用已在运行两种情况。

手机省电、后台限制、网络状态会影响执行时间。手动强行停止应用后，需要重新打开应用才能恢复；短暂停顿接话在前台最及时。此功能不适合用作必须准时送达的闹钟。

Windows 在后台程序运行时执行任务，即使浏览器页面已关闭也可以显示系统通知，点击通知打开对应聊天。电脑睡眠、关机或关闭后端时无法继续生成。可以在设置中发送测试通知；Windows 勿扰模式可能把通知直接收进通知中心。

两端聊天和计划仍各自保存在本机，不自动同步。

## API 用量

本地检查时间和频率不调用模型。开启的角色每次完成聊天后会增加一次联系计划整理请求；到达合适时机后，再调用模型决定是否发送并生成短消息。模型决定不发也会产生该次调用费用。主动任务使用有限上下文与非思考的辅助调用，不自动联网搜索。格式错误最多立即重试一次；仍失败时先按一分钟间隔重试，连续失败后等待一小时。其他模型请求错误等待一小时再尝试。

## 本次验证

覆盖三类触发、结束信号、免打扰、未回复限制、角色隔离、事件修改/取消、生成中收到用户消息、数据库租约和重启去重。浏览器覆盖设置保存、错误校验、375px 与横屏、增量消息节点保留、通知链接跳转。Android 打包脚本在桥接模拟环境中执行了后台生成和冷/热启动角色跳转；Windows 系统通知调用及通知中心内容已验证。

当前没有连接安卓真机，未验证实际设备上的 JobScheduler 唤醒、锁屏通知与不同厂商的省电策略。
